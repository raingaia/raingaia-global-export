The problem with signature-based detection

Tools like Snort or Suricata match live packets against a maintained rule or signature list — effective against known attack patterns, but structurally unable to flag a technique or destination that hasn't been catalogued yet. Raingaia Network takes a different approach: it learns what normal traffic looks like for each source on your network, and flags what deviates from that — including patterns no signature has ever described.

How it works

Three pieces, one flow: an edge agent captures and inspects live traffic on the host or segment you point it at; your own isolated analysis engine builds a per-source behavioral baseline and scores traffic against it across a physical channel (volume, timing, connection patterns) and a digital channel (protocol-level and content-derived signals); the console turns the fused result into a composite score and a named classification, refreshing every 5 seconds. What gets classified

Deep packet inspection extracts DNS queries, TLS Server Name Indication, HTTP host headers, and protocol behavior, mapped to a concrete event classification whenever a pattern matches a known attack shape:

ClassificationWhat it typically indicates
Port scanSystematic probing of multiple ports, characteristic of reconnaissance.
Probable C2 beaconSmall, evenly-spaced outbound connections to an unfamiliar destination.
DNS tunnelingAbnormal DNS query volume or entropy consistent with data smuggled through DNS.
Brute forceA high rate of repeated authentication attempts against a single target.
Lateral movementA source connecting to internal hosts it doesn't normally talk to.
Large transferAn outbound data volume anomalous against that source's own baseline.
ARP spoofingAddress Resolution Protocol activity consistent with on-path spoofing.
Illustrative example
A host began making periodic outbound connections to an unfamiliar destination on port 443 — small, evenly-spaced transfers with no matching inbound browsing activity. Nothing matched a known bad signature; the behavior itself, measured against that host's own baseline, is what stood out. Verdict: Critical — classified as a probable C2 beacon

Data isolation

Each paying customer is provisioned their own isolated analysis engine process and their own database — traffic, alerts, and investigation history for one customer are never mixed into another customer's data pool. This is a structural property of the deployment, not an access-control layer on top of shared storage.

Who it's for

Solo developers, small teams, and lean IT operations with an internet-facing host or network segment, real exposure to network-based threats, and no existing enterprise NDR budget or dedicated SOC analyst. It is not a replacement for a fully staffed enterprise SOC — it serves the gap beneath that tier.
