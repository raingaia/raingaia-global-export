The problem with signature-based detection

Tools like Snort or Suricata match live packets against a maintained rule or signature list — effective against known attack patterns, but structurally unable to flag a technique or destination that hasn't been catalogued yet. Raingaia Network takes a different approach: it learns what normal traffic looks like for each source on your network, and flags what deviates from that — including patterns no signature has ever described.

How it works

Three pieces, one flow: an edge agent captures and inspects live traffic on the host or segment you point it at; your own isolated analysis engine builds a per-source behavioral baseline and scores traffic against it across a physical channel (volume, timing, connection patterns) and a digital channel (protocol-level and content-derived signals); the console turns the fused result into a composite score and a named classification, refreshing every 5 seconds. Architecture: agent, engine, console

The edge agent is a single binary — Npcap on Windows, libpcap on Linux — that captures live traffic on the host or segment you point it at and runs deep packet inspection locally before anything leaves the machine. It extracts DNS queries, TLS Server Name Indication, HTTP host headers, and protocol-level behavior, then forwards the derived signals (not raw packet captures) to your gateway. There's no proprietary hardware sensor and no inline network placement required — it runs alongside normal traffic.

On the gateway side, your traffic reaches your own isolated analysis engine — not a shared multi-tenant pipeline. The engine builds the per-source baseline described above, runs the dual-channel and quantum-probabilistic scoring described in our technical approach, and writes results to your own database. The console reads from that same database and refreshes every 5 seconds — what you see is what the engine just decided, not a cached or batched summary.

Dual-channel scoring, applied to network traffic

The physical channel tracks volume, timing, and connection-pattern characteristics — how much data, how often, to how many distinct destinations. The digital channel tracks content and protocol-level signals — which domains are queried, which TLS SNI values appear, which HTTP hosts are requested, which protocol behaviors show up. Both channels are scored against that source's own baseline independently, then fused into the composite anomaly score. A source can look normal on one channel and anomalous on the other — fusing both is what catches things a single-channel tool misses.

Why this matters in practice
A compromised host beaconing to a C2 server often looks unremarkable on the physical channel alone — the transfers are small. It's the digital channel (an unfamiliar destination, evenly-spaced timing with no corresponding user-driven browsing pattern) that carries the signal. Scoring only traffic volume would miss it entirely.

Data isolation

Each paying customer is provisioned their own isolated analysis engine process and their own database — traffic, alerts, and investigation history for one customer are never mixed into another customer's data pool. This is a structural property of the deployment, not an access-control layer on top of shared storage.

Questions we get

How is this different from a signature-based IDS like Snort or Suricata?

Those tools match packets against a maintained rule list — effective against known patterns, blind to anything not yet catalogued. Raingaia Network scores behavior against a learned baseline instead, at the cost of a short warmup period to learn what normal looks like.
